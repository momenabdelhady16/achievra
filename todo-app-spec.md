# To-Do List App — Complete Project Specification

> **This document contains every detail needed to build the project from scratch.**
> Technology: HTML + CSS + JavaScript (Vanilla) — no frameworks.
>
> **Decision update:** This was the initial project brief. For decisions made later, the current requirements are in `00-index.md` and modules `01`–`06`; follow those when they differ from examples in this historical brief. In particular, IDs are generated by the repository, a task may have multiple dates, UI icons are SVG (no emoji icons), and the settled merge/sort/undo/action rules are in modules `02`, `03`, and `05`.

---

## 1. Principles

| Principle | Description |
|-----------|-------------|
| **SOLID** | Each module has a single responsibility |
| **Separation of Concerns** | Data, Logic, and UI are in separate files |
| **MVC Pattern** | Model → Service → View → Controller |
| **Desktop-First CSS** | Default styles target desktop; `max-width` media queries adapt down |

### Module Responsibilities

| File | Responsibility | SOLID Principle |
|------|---------------|-----------------|
| `taskModel.js` | Create and validate Todo model records and drafts | **S** — Single Responsibility |
| `TodoRepository.js` | Storage-independent asynchronous repository contract | **D** — Dependency Inversion |
| `LocalStorageTodoRepository.js` | Persist Todo records using localStorage | **S** — Single Responsibility |

| `TodoView.js` | Render the DOM, update UI, show/hide sections | **S** — UI only |
| `app.js` | Bind Service ↔ View, handle user events | **D** — Dependency Inversion |
| `textUtils.js`, `dateUtils.js`, `duplicateUtils.js`, `sortUtils.js` | Focused pure utility functions | **S** |

### JavaScript

| Type | Convention | Example |
|------|-----------|---------|
| Variables | `camelCase` | `taskTitle`, `isCompleted` |
| Classes | `PascalCase` | `TodoService`, `TodoView`, `Todo` |
| Constants | `UPPER_SNAKE_CASE` | `STORAGE_KEY`, `MAX_TITLE_LENGTH` |
| Functions | `camelCase` (verb + noun) | `addTodo()`, `deleteTodo()`, `renderList()` |
| Private methods | `_camelCase` | `_saveToStorage()`, `_generateId()` |
| Event handlers | `handle` + Event | `handleAddClick()`, `handleDeleteClick()` |
| DOM references | `camelCase` + `El` | `inputEl`, `listEl`, `headerEl` |
| Data attributes | `data-todo-*` | `data-todo-id`, `data-todo-action` |

### HTML

- Use **semantic elements**: `<header>`, `<main>`, `<aside>`, `<nav>`, `<section>`, `<ul>`, `<li>`, `<button>`
- Do **not** use `<div>` where a semantic tag applies
- All interactive elements must have accessible labels (`aria-label`, associated `<label>`)

## 8. MVP Features (Phase 1)

| # | Feature | Details |
|---|---------|---------|
| 1 | **Add task** | Input field + button. Press Enter or click to add. |
| 2 | **Display tasks** | Split into Pending and Completed sections. |
| 3 | **Select and complete tasks** | The native checkbox selects tasks; Mark Complete is a separate action. Completed tasks cannot be directly edited or toggled back. |
| 4 | **Delete task** | Mark the task muted for five seconds with an individual Undo control; delete permanently after the timer unless undone. |
| 5 | **Edit task** | Edit a Pending task's title, description, and due dates; IDs are immutable. |
| 6 | **Persist data** | Persist through the asynchronous repository contract, initially backed by `localStorage`; data survives page reload. |
| 7 | **Responsive layout** | Desktop sidebar + mobile off-canvas navbar. |
| 8 | **Empty state** | Show a friendly message when no tasks exist. |

## 10. Implementation Notes

- **CSS approach**: Desktop-first (default styles = desktop, then `@media (max-width)` for smaller)
- **CSS units**: All sizes in `rem` (base 16px). Breakpoints in `px`.
- **Storage**: asynchronous repository contract; initial LocalStorage adapter stores a versioned envelope and generates IDs.
- **No build tools**: Plain HTML/CSS/JS files loaded via `<script>` tags.
- **Accessibility**: All buttons have `aria-label`, focus-visible outlines, reduced-motion support.
- **Branding**: The approved brand name is **Achievra** and `favicon.svg` is the approved logo asset. Do not use Task Flow or placeholder branding. On tablet/mobile, show only the logo at the left of the navbar while the drawer is closed. When the drawer opens, hide the navbar logo and show the logo beside “Achievra” inside the drawer. UI action icons are SVG with descriptive visible labels; do not use emoji icons.
